## 二、发现的问题
### 问题1: PATH 严重重复
几乎所有用户级 PATH 条目都出现了 2~3 次，共 30+ 重复项。包括 nodejs 出现 3 次，nvm 出现 3 次。
### 问题2: nvm + nodejs 路径冗余
nvm 管理 node 版本，symlink D:\Program Files (x86)\nodejs → D:\Program Files (x86)\nvm\v22.22.2。但 PATH 中两个路径都存在，只需 symlink 路径即可。
### 问题3: 两套 GCC 编译器
- D:\Program Files (x86)\mingw64 → g++ 14.2.0 (MinGW-Builds)
- C:\msys64\mingw64 → g++ 16.1.0 (MSYS2)
功能完全重复，且 MSYS2 还自带 make 等工具更完整。
### 问题4: adb 路径冲突
scrcpy 自带的 adb.exe 在 PATH 中优先于 Android SDK 的 adb。当前 adb 命令指向 scrcpy 目录。
### 问题5: C 盘残留工具
Python, CMake, Docker, GitHub CLI, MSYS2 都在 C 盘，不符合"D盘集中"原则。
### 问题6: Rust 安装损坏
D:\tools\rust 有 cargo/rustup 目录但不在 PATH 中，安装不完整。
### 问题7: 散落的工具目录
Maven, MySQL, RocketMQ 直接散落在 D 盘根目录，没有统一管理。

## 三、整理方案
### 方案: 统一到 D:\dev 目录（参考结构）
```
D:\dev\
├── python\        ← 从C盘迁移 Python 3.12
├── go\            ← 从 D:\Program Files\Go 迁移
├── java\          ← Corretto JDK 17
├── rust\          ← 重新安装 Rust
├── mingw64\       ← 保留 MSYS2 (C:\msys64\mingw64 不动，软链接)
├── cmake\         ← 从C盘迁移
├── maven\         ← 从 D:\apache-maven-3.9.5 迁移
├── ffmpeg\        ← 从 D:\Program Files\ffmpeg 迁移
├── android-sdk\   ← 从 D:\Android\Sdk 迁移
├── git\           ← 保持 D:\Program Files\Git 不动
├── tools\         ← 保留 D:\tools (openssl-src, vcpkg)
├── databases\
│   ├── redis\     ← 从 D:\Program Files\Redis-x64-3.2.100 迁移
│   ├── mysql\     ← 从 D:\MySQL\MySQL Server 5.7 迁移
│   └── mongosh\   ← 从 D:\Program Files\mongosh 迁移
└── docker\        ← Docker 从C盘迁移较复杂，建议单独处理
```
### ⚠ 但是，直接迁移风险很大
1. 很多工具安装时写入了注册表、服务、内部路径，单纯移动文件夹会导致无法使用
2. MySQL, Redis, Docker 是注册为 Windows 服务的，迁移需要卸载再重装
3. nvm 的 symlink 和 settings.txt 需要一起改
4. 当前这些工具都能正常工作
### 推荐方案: 先修 PATH + 清理重复，以后新工具统一装 D:\dev
**第一步: 清理 PATH（安全，立刻见效）**
- 删除所有重复的 PATH 条目（30+ 个 → 降到 0 个重复）
- 删除多余的 D:\Program Files (x86)\nvm 条目（保留 symlink 路径即可）
- 确保 Android SDK adb 在 scrcpy 之前（或统一用 SDK 的 adb）
**第二步: 清理损坏项**
- 删除 D:\tools\rust（损坏的 Rust 安装）
- 删除 D:\tools\vcpkg（未引导的空壳）-- 除非你确实打算用 vcpkg
- 决定保留哪个 GCC: 建议只保留 MSYS2 (C:\msys64，版本更新)，删除独立 MinGW
**第三步: C盘工具处理**
- Python: 迁移到 D 盘需要重装（推荐 D:\dev\python），pip 包需要重装
- CMake: 可以直接移动文件夹 + 更新 PATH
- Docker: 绑定 WSL2，不建议动
- GitHub CLI: 可以直接移动 + 更新 PATH
**第四步: 新工具统一规范**
- 以后所有新开发工具统一安装到 D:\dev\<tool-name>\
- 新工具的 PATH 条目只加一次
**第五步: 环境变量迁移**
- 清理后 PATH 条目数可以减半
- 提供 PATH-MIGRATION.txt 记录变更前后对比，方便回滚

## 四、需要你决定的事
1. Python 要不要迁移到 D 盘？ 需要重装，pip 包要重装
2. Rust 还需不需要？ 如果不需要 Moonlight 编译了，可以不装
3. vcpkg 还需不需要？ 未引导的空壳，如果不需要可以删
4. 两套 MinGW 保留哪个？ 建议保留 MSYS2 (新版本 + 完整工具链)
5. Maven 还需要吗？ 如果不做 Java 项目可以不装
6. RocketMQ 还需要吗？ 如果不用可以删
7. Docker 要不要动？ 强烈建议不动，绑WSL2太深
8. 先只做 PATH 清理 + 重复项清理？ 还是要全面搬迁？
---
## 五、执行顺序建议
如果确认方案，执行顺序:
1. 备份当前 PATH（导出注册表或截图）
2. 清理 PATH 重复项（最安全的第一步）
3. 处理 Rust 残留 / vcpkg 空壳
4. 决定 GCC 选哪个
5. 处理 C 盘工具（CMake, GitHub CLI 可直接移; Python/Docker 需要重装）
6. 散落目录归档（Maven, MySQL, RocketMQ）
7. 新建 D:\dev 规范，写入 README
